================================================================================
REMCORDER — TECH STACK, ARCHITECTURE & PROJECT LAYOUT
================================================================================
GPU-accelerated screen recorder for Wayland: a Go background daemon that owns
the recording lifecycle, a Qt 6 / QML control center, a CLI client, and a
click-through QML overlay. Linux-only, Arch-first.

Repo:    github.com/remcostoeten/remcorder
License: MIT
Size:    ~5.000 lines across Go, C++, QML, shell


--------------------------------------------------------------------------------
1. LANGUAGES
--------------------------------------------------------------------------------

C++20            Qt control-center backend (RecorderBackend, ~1.500 lines).
QML (Qt Quick)   All UI: main window (~1.900 lines) + overlay (~200 lines).
POSIX sh         Prerequisite installer and the overlay launcher.
Make + CMake     Build orchestration.
YAML             GitHub Actions CI/release.

2. FRAMEWORKS & LIBRARIES
--------------------------------------------------------------------------------
Qt 6.5+          Core, DBus, Gui, Qml, Quick, QuickControls2, Multimedia, Network,

                 the system tray; QSettings persists per-user config.
LayerShellQt     wlr-layer-shell surfaces for the recording pill, keystroke strip
                 and standalone overlay so Wayland keeps them above all windows.

CMake 3.21+      qt_add_executable + qt_add_qml_module; -Wall -Wextra -Wpedantic.

External binaries invoked at runtime (not linked):
  gpu-screen-recorder   the actual capture engine — required
  ffmpeg                motion-blur copies and trim export — optional
  pactl                 microphone meter, gain, listen-back — optional
  xdg-open              open recording / folder after stop

3. ARCHITECTURE
--------------------------------------------------------------------------------
Four processes, deliberately decoupled so the recorder never dies with the UI.

  ┌─────────────┐   ┌──────────────┐   ┌────────────────┐
  │ remcorder   │   │ remcorderctl │   │ compositor     │
  │ (Qt 6 GUI)  │   │ (CLI)        │   │ keybind        │
  └──────┬──────┘   └──────┬───────┘   └───────┬────────┘
         │                 │                   │
         └────── JSON over Unix socket ────────┘
                           │
                  ┌────────▼─────────┐
                  │   remcorderd     │  owns lifecycle, single source of truth
                  │  (Go daemon)     │
                  └───┬──────────┬───┘
       spawns process │          │ atomic write
                      ▼          ▼
        gpu-screen-recorder    state.json  ──poll──►  overlay (QML, click-through)

CONTROL PLANE
  Socket: $XDG_RUNTIME_DIR/remcorder/remcorder.sock
          (override with $REMCORDER_SOCKET; falls back to /tmp/remcorder-$UID/)
  Protocol: one JSON Request in, one JSON Response out, per connection.
  Actions: status | start | stop | toggle | pause | resume | toggle-pause
  Defined in internal/control/control.go — shared by daemon, CLI, and GUI.

STATE PLANE (one-way, read-only for consumers)
  The daemon atomically rewrites a JSON snapshot in the runtime dir on every
  state change. The overlay polls that file and never sends commands, so the
  indicator can crash, restart, or be absent without touching a recording.
  With -keystrokes it publishes a second snapshot, keys.json, on the same
  terms. Qt refuses XMLHttpRequest reads of file:// unless
  QML_XHR_ALLOW_FILE_READ=1, which scripts/remcorder-overlay exports.

KEYSTROKE PLANE (internal/keystrokes, opt-in)
  Wayland gives no client the global key events a screencast overlay needs, so
  the daemon reads /dev/input evdev nodes directly, filtered by their EV_KEY
  capability bitmap rather than by name. Devices are opened only while a
  recording runs and closed on stop or pause; nothing is persisted.

RECORDER ENGINE (internal/recorder)
  Wraps gpu-screen-recorder as a child process group. Pause/resume via signals
  to the group; stop sends SIGINT so MP4 containers are finalized instead of
  truncated. Stale sockets are cleaned on startup.

DESIGN RULES ENFORCED BY THE LAYOUT
  - The daemon is the only thing that knows recording state.
  - UI is replaceable: GUI, CLI, and overlay are all just clients.
  - Post-processing (motion blur, trim) always writes a NEW file
    (-blur.mp4 / -trim.mp4); source recordings are never mutated.

--------------------------------------------------------------------------------
5. BUILD, TEST & RELEASE
--------------------------------------------------------------------------------
make check      go test ./... + go vet ./... + Release CMake build + qmllint
                → this is the pre-push gate; CI runs exactly this.
make            builds remcorderd, remcorderctl, and the Qt GUI
make install    installs to ~/.local, drops user units, daemon-reload
make tray       install + autostart entry + relaunch into the tray
make uninstall  removes binaries, units, desktop entries

CI       .github/workflows/ci.yml — archlinux:base-devel container, runs
         `make check` on push/PR to the default branch.
RELEASE  .github/workflows/release.yml — on `v*` tags: check, git-archive
         source tarball, stamp pkgver, makepkg as an unprivileged user,
         upload the .pkg.tar.zst + PKGBUILD to a GitHub Release.

Install targets: Arch family (packaged), Debian/Ubuntu, Fedora/RHEL, openSUSE
(build deps only — gpu-screen-recorder must be installed manually there).
